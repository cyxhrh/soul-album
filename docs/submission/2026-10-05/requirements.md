## 3. 官方部署资料已核验的事实

直接依据 [ModelScope 官方组织的 Studio 部署说明](https://github.com/modelscope/modelscope-skills/blob/main/skills/ms-studio-deploy/SKILL.md)及[官方 Docker 模板](https://github.com/modelscope/modelscope-skills/blob/main/skills/ms-studio-deploy/references/docker-templates.md)：

- Docker 方式识别仓库根目录 `Dockerfile`，服务监听 `0.0.0.0:7860`；本次核验不是 7000。`EXPOSE` 不能代替实际监听配置。
- Static SDK 只接受已构建的站点入口，不执行构建。React/Vite 源码需要先构建，或者使用 Docker 构建。
- Docker 需 ModelScope 账户完成阿里云绑定和实名认证。硬件选项及免费额度应查看创建页或当前 API 返回；不要把某个示例 CPU 规格保证为永久免费。
- 官方工作流通过 Git 同步代码，空间默认分支为 `master`，更新后触发部署，并检查构建与运行日志。不能假定推送 GitHub 自动部署创空间。

2026-10-05 再次读取[官方说明原始文件](https://raw.githubusercontent.com/modelscope/modelscope-skills/main/skills/ms-studio-deploy/SKILL.md)，上述要求仍适用。账号、硬件、可见性确认后创建/更新空间，Git 同步代码，再部署并查看日志，最后检查真实体验地址；当前静态 Demo 无需新增模型服务密钥。

官方网站入口：[创建与搭建](https://modelscope.cn/docs/studios/create)、[Docker 创空间](https://modelscope.cn/docs/studios/docker)。本轮访问能读到页面标题，但正文为动态加载，未取得完整页面；以上运行要求由官方 GitHub 文件交叉核验。

`ms_deploy.json` 可作为配套配置模板，但所核验的官方 Git 工作流未将它列为必须文件。实际 SDK、硬件、权限与环境配置以队友当前创建页/空间设置为准。

## 4. 给队友的可行发布顺序

本节是针对本项目的操作建议。空间创建页具体按钮名称可能随平台更新，不能当作本轮已操作验证过的 UI。

1. 从 GitHub 的交接分支获取本目录和最新源码，阅读 `deployment.md`，本地先打开固定流程 Demo。
2. 登录 ModelScope，从创空间入口创建程序化空间；使用 Docker 类型，确认需要的绑定/实名步骤和可用免费 CPU 资源。若当前 UI 提供上传文件/快速部署，则上传本项目部署包并按其设置选择 Docker；不要启用未确认收费的资源。
3. 更稳妥的替代是使用新空间页面提供的 Git 仓库地址：克隆该空间，在副本中放入项目文件，检查 `Dockerfile` 位于根目录，然后提交并普通推送到空间实际默认分支。GitHub 分支与空间仓库保持独立，不强推、不覆盖已有空间内容。
4. 按空间 UI 启动/部署，查看 build 日志和 run 日志，等到 Running 再打开应用。详细命令及项目文件清单见 `deployment.md`。
5. 该比赛路径使用预设合成资料，静态容器不需要模型密钥。只上传源码、公开素材、合成证据与本目录材料。不要把本机 `.env`、访问令牌、私人画册或原始私人聊天混入空间或 GitHub。
6. 把真实空间 URL 记入交接清单；用未登录浏览器核验从首屏进入五轮聊天、原话来源、纠正卡、画册、日常及下一次见面的完整体验，再粘贴到比赛应用字段。

Git 远程认证请用平台说明的正常凭据机制，避免将带令牌的远程地址写进文档、截图、GitHub 或命令输出。此处不预填账号、空间名或令牌。
