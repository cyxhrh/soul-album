# 本机逐轮千问对话试验契约

> 历史试验记录：本文件描述旧版“每句预览并同意”的路径。默认产品现已改用[统一模型对话契约](auto-chat-v2.md)，不再出现逐句授权弹窗；保留本文件仅用于理解先前实现和合成实测。

**范围：比赛 Demo 的可选本机路径。** 默认规则对话仍可在没有密钥时使用；公开 GitHub Pages 只承载静态前端。此接口不是生产级私人云服务，不提供账户鉴权、加密持久化或跨设备同步。

## 一轮如何发生

1. 用户在唯一消息框中输入自然语言。原话先进入当前页面的本地内存记录，不等模型决定它是“回答”“分享”还是“跳过”。用户不必按行为模式按钮，也不受当天邀请题数限制。
2. 页面展示**这一轮将发送的完整 JSON**，包含当前原话的一段、用户勾选的至多两段仍有效的旧原话，以及上一轮仍有效的模型回应（如有）。页面可让用户删减或取消旧片段；正文只能截取原话中的连续片段，不能改写成看似用户说过的内容。当前原话是调用所必需的，用户可删减它或取消本次请求。预览中的每个来源都有 ID、修订号与演示日号；这些元数据也会传给本机代理。只有点击本次同意，才会请求 `POST /api/ai/private-chat`。一次同意只授权这一轮，不默许后续轮次。
3. 本机代理只在显式开启私人聊天开关、配置百炼密钥时请求千问。模型生成一段自然回应和可选追问，并可引用已批准片段。模型输出只是**聊天建议**；记录、编辑、删除、授权和本地画册仍由程序处理，不把模型推断写成用户事实。引用需要逐字出现在本轮允许发送的片段中；通过字面检查不代表语义正确。
4. 用户可以继续在同一个框里自然回答、转移话题、说“不是这个意思”或结束谈话。更正作为用户自己的新原话保存，下一次调用仍需单独预览并授权。拒绝、取消、断网、模型失败或配额耗尽时，原话保持在本地；界面明确说明没有生成千问回复，不伪造模型输出、不自动重试。

发送前与响应后，页面均复核来源是否还是当前版本。若这期间修改／删除了任何已发送的来源，或重置了会话，迟到结果不可进入聊天。已经展示的模型回复若依赖的来源失效，亦须撤下。点击发送后取消可放弃结果并尝试中止上游请求；已发出的明文无法撤回，且可能计费。

## 本机 HTTP 形状

`POST /api/ai/private-chat` 接受同源 `application/json`。示例仅用于说明结构，不是调用证据：

```json
{
  "turn": {"kind":"entry","id":"entry-2","revision":1,"day":2,"quote":"今天下班时看到晚霞。"},
  "context": [
    {"kind":"entry","id":"entry-1","revision":1,"day":1,"quote":"昨天说想留一点散步时间。"}
  ],
  "precedingAssistant": {"reply":"下班路上的晚霞听起来让你停了一下。","nextQuestion":"你想记住当时的什么细节？"}
}
```

`turn` 必填且只来自这次用户发送；`context` 最多两条，只能从当前有效的用户记录中选择。每段 `quote` 为 1–800 个字符，ID、版本和日号供浏览器核验；`precedingAssistant` 只允许上一条仍有效且在预览中展示的模型文字。服务器没有浏览器的本地记录库，只能核验请求形状，不能独立证明这些 ID、修订号、片段和本次点击是真实的。当前与旧片段、以及此前回应的文字可能被转发到模型；界面必须如实告知。请求体大小、回环 Host／Origin、调用次数、速率、超时和无重试由代理限制。

成功响应形状：

```json
{
  "status":"generated",
  "reply":"你留意到了下班路上的晚霞。",
  "nextQuestion":"那一刻你最想记住什么？",
  "citations":[{"id":"entry-2","quote":"下班时看到晚霞"}],
  "model":{"provider":"qwen","id":"configured-model-id"},
  "generatedAt":"2026-09-29T00:00:00Z"
}
```

`reply` 为 1–280 字；`nextQuestion` 可为 `null`，若有须为 6–100 字且以问号结尾；`citations` 最多三条，每条引用的 `id` 要在本次批准的 `turn` 或 `context` 中，`quote` 必须是对应片段的非空逐字连续子串。页面不得把这些字段当作自动日记、诊断或已证实的画像。响应不应附带未批准的记录正文。失败仅返回安全错误码，不回传密钥、Prompt 或上游正文；响应应使用 `Cache-Control: no-store`。

## 启动与验收

Windows 本机先打开一次独立的遮蔽输入窗口，只在标题为“心灵画册 · 保存百炼 Key”的窗口中输入 Key；随后构建服务、启动前端，以后启动器会自动读取当前用户的 DPAPI 加密副本。例如在确认模型及可能费用后运行：

```powershell
powershell -NoProfile -STA -File scripts/save-qwen-key-gui.ps1 -Region cn
npm run build:server
npm run dev -- --host 127.0.0.1 --port 5175 --strictPort
powershell -NoProfile -File scripts/run-qwen-local.ps1 -Region cn -Model qwen3.8-flash -EnablePrivateChat -MaxCalls 3
```

第一条只需在当前 Windows 账户执行一次，后续三条在各自终端运行，最后的服务窗口保持开启。默认启动若无已保存 Key 会报错，不会再要求终端输入。保存文件位于用户 `%LOCALAPPDATA%\SoulAlbum`，不在仓库；可用 `scripts/save-qwen-key.ps1 -Region cn -Status` 核对、用 `-Remove` 删除、重新打开遮蔽窗口覆盖本机副本。轮换时还须在百炼控制台撤销旧 Key。`-MaxCalls 3` 是**本次进程**最多三次上游尝试，错误也计数，重启会重置，不能当作费用上限。不要把密钥放进普通终端、聊天、源码或 `VITE_` 环境变量。默认不开启此端点。

最小验收用合成人物连续聊三轮：分享一件事、接着回应、再纠正一次理解。每一轮均检查预览与实际请求一致，取消时零请求，模型回复和追问在当前气泡中可见；再试断网或模拟提供方失败，确认原话仍留本地且没有伪造回复。之后编辑／删除一条已经引用的来源，验证依赖回复撤下；刷新页面验证本地内存清空。假提供方测试只能证明接线与边界，不能证明真实模型可用；真实百炼调用须另留不含密钥的合成输入及结果证据。

百炼[官方隐私说明](https://help.aliyun.com/zh/model-studio/privacy-notice)称客户数据不用于模型训练，也表明会存储模型与应用调用产生的数据。页面清除只影响本应用当次内存，不能清除已发送到提供方的副本。这里仅用合成记录验收，暂不输入真实私人经历。
