# 本机主对话千问逐轮试验 · 2026-09-29

**目的：** 验证主对话的用户输入会经本机单次隐私门到达真实千问，并以独立模型气泡返回；仅使用合成日常故事。此记录不证明长期对话质量，也不涉及真实用户日记。

**环境：** Windows 本机回环服务 `127.0.0.1:8787`，百炼中国内地地域，`qwen3.8-flash`，私人聊天端点单独开启，本次进程最多 3 次上游尝试。密钥在本机 PowerShell 无回显输入，未进入浏览器、仓库或本文。

| 轮次 | 本轮合成原话 | 本轮实际发送的上下文 | 页面所见 |
| --- | --- | --- | --- |
| 1 | 今天下班时看到晚霞，我站在路边看了一会儿。 | 无 | 千问回复：“那片刻的停留，一定让忙碌的一天有了温柔的收尾。”；追问：“当时心里在想些什么呢？” |
| 2 | 我当时只是觉得颜色很好看，也想让自己慢下来。 | 勾选第 1 轮原话与上一轮千问回复／追问 | 千问回复：“被色彩吸引，顺便给自己按个暂停键，这种时刻很珍贵。”；没有追问。 |
| 3 | 你说“珍贵时刻”有点重了，我只是随手看了看晚霞，想把这件小事记下来。 | 勾选前两轮原话与上一轮千问回复 | 原话留在聊天和画册；这次没有模型气泡。旧版前端只显示笼统的“服务暂不可用”，因此无法从该页面判断是上游、配额还是模型格式校验。 |

三轮都由网页主对话同一输入框提交，每轮先保存本地，再展示包含 ID、修订号、演示日号、选定原话及可选历史的完整 JSON，点击单次同意后才请求。服务端只将获准的 `id/kind/day/quote` 和选定的上一轮回应传给千问，修订号只用于本地时效校验。第 3 轮未自动重试，也没有伪造回复。

发现第 3 轮的错误提示过于笼统后，前端已改为仅根据后端白名单状态码和错误码显示限流、模型输出校验、上游不可用或超时等安全说明；绝不展示上游原文。提示词中的 JSON 格式示例也改成两份可解析的合法 JSON。旧第 3 次请求的实际错误码没有被记录，因此不能倒推故障原因，也不能把它计为通过。

用户另行同意**追加一次可能计费的合成数据试调用**。更新后的服务以 `-OneCall` 启动，本次直接向同一个 `/api/ai/private-chat` 端点发送旧第 3 轮的合成纠正文本、前两句合成原话与旧第 2 轮的模型回应；没有使用真实用户资料，也没有再次调用前两轮。返回 HTTP 200、`status=generated`、模型 `qwen3.8-flash`：

> 收到，是我把词用重了。随手记下晚霞的颜色和那份慢下来的感觉，本身就很好。

`nextQuestion` 为 `null`；两条引文均是本次获准合成原话的逐字子串。**这次证明更新后的后端与真实模型能处理纠正轮次；它是直接 HTTP 复测，不等于更新后的浏览器已经完整重新走过三轮真实模型。** 前端对不同安全错误码的展示由假 provider 浏览器测试覆盖。

自动化佐证：重构后 `npm run build:all`、`npm run test` 229 项、`npm run lint` 和顺序执行的 `npm run test:e2e` 78 项通过。浏览器测试使用假 provider，覆盖三轮连续聊天、预览与实际 POST 一致、取消零请求、502 错误保留本地原话、来源编辑后的依赖气泡撤下、迟到响应等。假 provider 的通过不能替代上面真实模型试验的局限。
