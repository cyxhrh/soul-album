# 每日画册正反面设计草案

日期：2026-09-30
基准：teammate-frontend 工作树，5176 预览。
状态：核心方案已于 2026-10-01 落地，实际能力与验证见 [本轮交付](jianzhi-competition-upgrade-2026-10-01.md)。本文保留设计目标；独立历史回退、任意 Markdown 导入和跨日模型检索暂未实现。当前版本仅保存有效修订，采用生成结果前可比较，编辑草稿可下载。

## 用户目标

每日画册有两种呈现：正面是经过美化排版、精炼简洁、方便回看的日记；背面保留用户原文、模型回答和基于当天回答形成的今日肖像，以 Markdown 记录，方便模型理解以及用户查阅、修改。

比赛阶段优先实现一日内的完整体验，长期跨日检索、自动人格画像与设备接入仍不属于本轮范围。

## 页面设计

- 日期导航保持现有机制；切换日期和正反面是两个独立操作。
- 每日页顶部提供“日记正面 / 记录背面”文字切换，同时用轻微翻面动效表达关系。键盘可操作，减少动态效果偏好下不播放翻面。
- 正面：日期、可改标题、约 100–250 字的精简日记、可选一条原话。字数为排版目标，不足时不凑字，复杂经历不为字数截断重要转折。
- 正面不展示完整问答、画像字段或技术元数据。标注“由当天对话整理，可修改”，不把模型补写包装为用户原话。
- 背面默认是可读 Markdown 预览，提供“编辑 Markdown / 保存 / 取消 / 下载 .md”。手机全宽单页，桌面保持画册视觉。
- 切换展示面不调用模型。新增聊天后提示“记录有更新，可重新整理”，不强制离开聊天。

## 一天一份记录

建议文件名：YYYY-MM-DD.md。内部独立日页 ID 避免演示日期、实际录入日期以及多空间之间发生覆盖。

结构包括：

1. 元数据：记录日期、时区、版本、更新时间、生成模型、整理覆盖范围。演示日期和实际发生/录入时间分开标明。
2. 日记正面：标题、精简正文、可选原话引用。
3. 完整对话：稳定消息 ID、角色、顺序、时间、完整内容；用户文本、AI 回答、系统开场分别标记。
4. 今日肖像：当日明确事实、用户自述感受/需求、模型暂定观察、依据消息 ID、不确定之处。只有少量记录时允许“信息不足”。
5. 用户修正：修正对象、修改内容、当前有效版本。历史修订不作为有效事实再次送入模型。

全文用户消息来自原始记录，不能使用聊天请求目前仅有的前 800 字片段充当完整原文。AI 回复来自真实已完成响应；加载、失败和固定界面提示不能伪装成模型回复。

## 生成与修改

- “整理今天”显式触发本日精简日记和今日肖像生成；完整对话记录不依赖生成成功。
- 一次生成共同产生正面和今日肖像，并引用同一版本原文，避免各自读取不同记录。
- 整理请求检查覆盖范围；不得无提示截断，超出支持容量时明确提示并保留原文，分段整理作为后续扩展。
- AI 观察始终是暂定理解，不能从当天一句话推导固定性格；模型重复引用自己的分析不构成新证据。
- 用户可以修改正面、原文、模型回复文本和画像；修改过的历史消息标为用户修订，不冒充当时原始输出。
- 原文或事实被修正时，关联摘要和肖像标记待更新，并停止作为模型的有效依据；用户编辑过的正文不被后台生成静默覆盖。
- Markdown 保存先预览变更并校验结构。错误保留草稿并解释问题，不丢内容。首次不做任意 Markdown 文件的无损导入承诺。
- 历史修订在独立修订存储中保留供用户回退，模型默认只接收当前有效内容。明确删除的内容及其派生信息应一并清除，不以版本历史为由暗中保留。

## 比赛版保存方式与模型读取边界

建议第一版采用浏览器本机持久保存每日 Markdown 及必要索引，刷新后恢复；提供真实 UTF-8 .md 文件下载。浏览器内保存和写入电脑文件夹是不同能力，界面必须如实说明。自动同步 Obsidian 或指定目录不属于已完成能力。

模型读取由应用构建的当前有效记录：原话、用户修正优先；AI 暂定分析单独标识。Markdown 是参考资料，其中的文本不是系统指令，不能由导入或编辑内容改写角色和权限。

第一版以本日整理为模型读取的实际闭环，生成时把当天完整对话提供给现有模型服务并明确说明发送范围。普通聊天当前仅有有限上下文，不宣称已拥有跨日记忆；后续让聊天按需读取每日档案时，应另行对齐接口及范围。

## 实施顺序

1. 以明确标注的合成样例完成正反面视觉、翻面、Markdown 预览和编辑原型。
2. 汇总真实当天消息与模型回答，完成持久保存、下载和修订流程。
3. 接通一次本日整理请求，返回正面日记与有依据的今日肖像，处理覆盖不足和失败状态。
4. 将聊天入口定位到当天正面，完成电脑、手机和比赛演示路径检查。

## 验收

- 一眼可区分日记正面与记录背面，切面不会触发请求或丢失编辑。
- 导出的 .md 与页面当前有效内容一致，中文、换行及带 Markdown 符号的原话完整保留。
- 用户长消息末尾的重要转折保留在背面；整理缺少覆盖时不会产生“已完整理解”的假象。
- 原文修正后旧肖像不再作为有效依据，用户修改的日记不会被静默覆盖。
- 生成失败不影响原文查阅和导出，刷新后已保存内容可恢复。
- 合成展示数据与真实用户记录分开；普通聊天不会被宣称具有尚未接通的跨日记忆。
